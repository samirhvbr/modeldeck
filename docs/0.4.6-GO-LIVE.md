# ModelDeck 0.4.6 go-live

This is the release-day sequence, not an automated release. Run it only after
the signed 0.4.6 artifact exists. The installed 0.4.6 daemon must be answering
before any analytics cutover step; 0.4.5 has none of this machinery. Commands
use placeholders and never print identities, credentials, or database rows.
Run every command from the clean ModelDeck checkout that built the signed
artifact; the first verification confirms that checkout and daemon match.
Stop at the first failed verification.

## 1. Install 0.4.6

Quit ModelDeck, install the signed 0.4.6 DMG into `/Applications`, then launch
it and allow the bundled service upgrade to finish.

Verify:

```sh
test -z "$(git status --porcelain)"
test "$(curl -fsS http://127.0.0.1:3867/api/health \
  | jq -er 'select(.ok == true and .version == "0.4.6" and .tokenSource == "keychain")
    | .MDGitCommit | select(type == "string" and length > 0)')" \
  = "$(git rev-parse HEAD)"
```

## 2. Tim-gated dashboard flag flip

The source default is ON for a new 0.4.6 settings document, but an existing
database's stored value is deliberately untouched. Tim flips **Settings →
General → Enable the usage analytics dashboard** ON.

Verify:

```sh
curl -fsS http://127.0.0.1:3867/api/settings \
  | jq -e '.usageAnalyticsEnabled == true'
```

## 3. Retire both old consumers, then hand the queue to the daemon

Retire the interim warehouse job and legacy destructive queue poller in one
operation. This is a manual ops step; no application code unloads launchd jobs.

```sh
scripts/retire-usage-poller.sh
```

Verify both are absent — the check is loud in both directions and stops the
runbook if either job is still loaded:

```sh
verify_absent() {
  launchctl print "gui/$(id -u)/$1" >/dev/null 2>&1; status=$?
  case $status in
    3|113) echo "OK: $1 absent" ;;
    *) echo "STOP: $1 still loaded (launchctl status $status) — do not proceed" >&2; return 1 ;;
  esac
}
verify_absent ai.hermes.modeldeck.ingest || exit 1
verify_absent com.cliproxyapi.poller || exit 1
```

Then enable the daemon consumer. Pass the existing ModelDeck mutation token
from its Keychain entry to this command only, without printing or retaining it
in the shell. The helper sends only the cutover field, so every other stored
setting is preserved:

```sh
set +x
MODELDECK_MUTATION_TOKEN="$(scripts/set-mutation-token.sh --show)" \
  node scripts/enable-usage-queue.mjs
```

Verify the single-consumer guard and first pull are visible:

```sh
node scripts/verify-usage-queue-guard.mjs
```

The same handoff is logged as `USAGE QUEUE DAEMON CONSUMER ARMED`; a conflict
is logged as `USAGE QUEUE FOREIGN CONSUMER DETECTED` and is also present in
API state.

If state says `blocked` or `unknown`, stop. The daemon has not consumed the
queue; read `.usageQueue.guard.message` and the ModelDeck error log.

## 5. Orchestrator end-to-end field verify

Run the supported release checks, then run one placeholder test session through
the installed 0.4.6 path. Immediately after the session finishes, record the
time and wait for both daemon-owned recurring loops: the five-minute usage-queue
consumer and the 15-minute warehouse pass. The latter runs the transcript
archive ingest, Codex rollout ingest, and usage-estimate refit in-process; its
state records all three jobs, and a failure in one job is logged without
stopping the other jobs or the next pass.

Check the rendered dashboard: Overview loads, the deterministic provider stack
keeps Codex at the baseline after a Claude → Codex → Combined round-trip,
project drill opens, and session anatomy shows the new session. Do not inspect
live SQLite directly.

Verify the supported release checks and wait up to 16 minutes for a warehouse
pass completed after the placeholder session:

```sh
set -euo pipefail
npm run release:check
# Run the placeholder session now, then record its completion boundary:
session_finished_at="$(node -e 'process.stdout.write(new Date().toISOString())')"
deadline=$((SECONDS + 960))
# Gate on every job SUCCEEDING; warnings do not block (a single skipped
# malformed transcript must not stall go-live) but are printed for review below.
until curl -fsS http://127.0.0.1:3867/api/state \
  | jq -e --arg after "$session_finished_at" '
      .warehouseIngest.configured == true
      and .warehouseIngest.running == true
      and .warehouseIngest.intervalSeconds == 900
      and .warehouseIngest.lastPass.startedAt >= $after
      and (.warehouseIngest.lastPass.jobs | keys == [
        "codexRollouts", "transcriptArchive", "usageEstimateRefit"
      ])
      and ([.warehouseIngest.lastPass.jobs[]
        | select(.ok != true)] | length == 0)
    '; do
  test "$SECONDS" -lt "$deadline" || { echo 'STOP: no clean warehouse pass before deadline' >&2; exit 1; }
  sleep 5
done
# Review before release: nonzero warnings mean skipped records — investigate.
curl -fsS http://127.0.0.1:3867/api/state \
  | jq '.warehouseIngest.lastPass.jobs | map_values(.warnings)'
curl -fsS -o /dev/null http://127.0.0.1:3867/dashboard
node scripts/verify-usage-queue-guard.mjs
```

Optional first-boot warm-up only: the commands below populate the warehouse
immediately if the operator does not want to wait for the first daemon pass.
They do not schedule future work and are not the ownership mechanism; the
daemon state check above is still required.

```sh
set -euo pipefail
npm run -s transcripts:ingest | jq -e '.warnings == 0'
npm run -s usage:ingest:codex \
  | jq -e '(.warnings | [.[]] | add) == 0'
npm run -s usage:estimate:refit \
  | jq -e '.pools == 1 and ((.fitted + .unavailable) == 2)'
```
