Adding a Grok subscription

Issue #560. Claude and Codex are added by creating a fresh, ModelDeck-owned profile folder and handing off to the provider’s sign-in. Grok has neither: the grok CLI owns ~/.grok and does its own auth. So the Grok entry does the honest thing instead — it points ModelDeck at the grok home that already exists, read-only, and skips the sign-in step entirely. Two steps instead of three, in the same 420 pt sheet, with no new window. Placeholder identities only.

No sign-in step, no Terminal handoff, no “Signed in as…”.

Grok has no per-account profile home for ModelDeck to create and no login for it to launch, so the middle step of the Claude/Codex flow simply is not there. Claude and Codex keep all three steps, unchanged.

The confirm step earns its place by proving the connection works. Claude and Codex confirm with an identity read-back (“Signed in as …”); ModelDeck never opens Grok’s credential, so it has no identity to show. The billing reading is the honest equivalent — and it is the same reading the deck card uses, so a card that can never fill in fails here, at connect time, rather than silently.
